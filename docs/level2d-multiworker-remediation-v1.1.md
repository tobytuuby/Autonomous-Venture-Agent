# Level2D bounded three-worker remediation v1.1

This version amends [v1.0](level2d-multiworker-remediation-v1.0.md) only for
legacy Worker policy compatibility and records the owner's 2026-10-31 scoped
activation instruction. All v1.0 authority, isolation, signature, dependency
and evidence requirements continue to apply. Historical documents and artifacts
remain preserved. This authorizes no production CEO, launch, payment or capital.

The shared inference policy may contain the exact four actors service-worker,
worker-a, worker-b and worker-c. Other four-actor sets and larger lists are denied.
The legacy one-actor policy and existing lists of at most three actors retain
their validation behavior. This adds an actor compatibility allowance, not a
request allowance. The assignment maximum remains four calls. The existing
atomic Control ledger still enforces the venture-wide ceiling of four,
including prior workflows and policy epochs. No reset, refund, new venture
alias, quota expansion or replacement ledger is permitted by this increment.

The technical fixture remains level2d-multiworker-remediation-1 under
venture-verification. Its existing five-effort-unit signed scope is unchanged
and below the owner's fifteen-unit maximum. The reasoning request policy remains
eight and the shared Worker request policy remains four; their combined request
ceilings are twelve. Effort units, request counts, output tokens and currency
are separate bounds. seed_cents remains a synthetic scope field and authorizes
no spending. Models remain the inspected gpt-6-sol for CEO/Manager and
gpt-6-luna for Workers.

A/B have independent assignments; C depends on both. Decomposition must be
CEO-signed before Worker inference, and the last allowed terminal transition
is CEO OWNER_REVIEW. A service being active does not establish any of those
acceptance results.

The Control activation script uses inspected-file comparisons, private backups,
SQLite backup copies, atomic replacement and broker restart with rollback.
It changes only the Worker validator, shared Worker policy and inactive
technical CEO workflow/session binding. It does not start the CEO, create a
workflow, sign a command or call a provider.

The separately staged Agents operator script compares deployed public source
hashes, authenticates a read as Manager to require an absent target workflow,
preserves Manager and Worker configurations, installs the matching shared
policy in the three private Worker homes, and switches Manager's workflow,
session and decomposition mapping. Existing identity/key references remain.
It must run from the approved Agents project as an authorized operator root;
the bridge's no-new-privileges boundary must not be bypassed. It does not solve
quota exhaustion or authorize subsequent inference.

For this attempt, signed-journal inspection resolves five existing Worker
reservations to venture-verification against the unchanged four-call ceiling.
Real model calls cannot proceed under that budget. Configuration activation
and local synthetic tests must therefore be reported separately from an
unexecuted real-provider acceptance journey. Further model execution requires
a separately authorized, versioned budget resolution; changing workflow ID
cannot replenish this venture.

for executed actions, process/log records, results and remaining privilege gates.
