# Level 2C central inference reservations — distinct CEO and Manager identities
Version: 1.1 | Date: 2026-10-29 | Coding baseline: e671a6f0462708876058c3ccf1686778c477f9ce

Supersedes the integration contract in [v1.0](level2c-central-reservation-phase1-v1.0.md). Historical evidence remains unchanged. This is a code and isolated-test increment, not production activation or venture approval.

- Control owns one ProviderQuota directory beneath its deployed repository's ignored artifacts. The directory must be owner-controlled mode 0700; authority and standing usage policy remain separately provisioned private operator files. No secrets, certificate material, policy provisioning, service changes or deployment are included.
- The existing HTTPS mTLS broker keeps its capability and Manager polling pinsets. Optional VENTURE_BROKER_CEO_RESERVATION_PINS and VENTURE_BROKER_CEO_RESERVATION_ACTOR configure the dedicated CEO reservation identity. Both settings must be supplied together. All three certificate pinsets must be disjoint, and the two reservation actors must differ. VENTURE_BROKER_RESERVATION_ACTOR continues to bind the Manager polling certificate to its fixed Manager actor.
- The exact POST /v1/inference/reservations route derives actor and role from the verified TLS certificate pin. Body actor/role values are assertions checked against that identity, never authorization. Capability pins cannot reserve. CEO reservation pins cannot poll, acknowledge, evaluate capabilities or read capability health. Manager pins cannot reserve as CEO.
- The first authorized CEO reservation may create the private central ledger and bind a session to its exact context and operator policy. Manager reservations require that CEO-established session and matching binding; Manager requests cannot initialize a missing ledger or session. Session binding, daily charging, call ceiling and durable retry identity share one SQLite writer transaction.
- Both provider-backed preparation entrypoint roles use RemoteStandingModel through PreparationPollClient's authenticated HTTPS client. Both require endpoint, ca_file, client_cert, client_key and usage_policy configuration. CEO uses its dedicated reservation certificate; Manager uses its polling certificate. The policy copy requests limits; only the broker's operator files authorize them. No local quota fallback exists. StandingModel rejects provider-backed local use; synthetic local fixtures remain for prior accepted coverage.
- Exact reservation retries return the same receipt and consume one charge. Changed attempts, request hashes, context or policy are denied. A lost reservation response holds the local inference intent; it cannot trigger a provider call or local fallback. Concurrent first CEO reservations serialize against the same ledger.
- Existing Level 2B mTLS, signed assignment/acknowledgement and preparation-only boundaries remain in force. No CEO attachment, capital, payment, launch, worker execution or production activation is authorized.

[Validation evidence](level2c-central-roles-evidence-20261029.md) distinguishes isolated execution from independent review and deployment evidence. ADV-001–ADV-049 remains /49; these integration tests are supplemental.
