## Evidence structure and denominator

The 81 authority cases and 12 recovery cases are generated from the committed registry and are independently addressable by case ID. The unittest `subTest` parameterization is only the execution structure; it does not collapse the evidence denominator. Each case invokes the controller separately and emits one JSON envelope named from its case ID. The committed registry is the audit-readable source for the exact denominator and dimensions.

The integration test exercises authority, ledger, and credential blocking drift as separate events and verifies independent freeze/evidence results. The volume test exercises 100 distinct synthetic blocking events and verifies one evidence envelope per event, fixed five-second preservation latency, and matching evidence hashes. Neither test performs external actions.

## Behavior implemented

The P7 controller now:

- classifies observations as ZERO, TOLERATED, or BLOCKING;
- treats authority, ledger, provenance, credential, customer-state, policy, and configuration drift as blocking;
- supports bounded tolerance rules only for explicitly configured non-blocking drift types;
- invokes a caller-supplied synthetic freeze boundary for blocking drift;
- records freeze status and action identity;
- preserves a separate immutable JSON evidence envelope;
- computes an evidence SHA-256 over the envelope before adding the self-hash;
- records detection, preservation, and preservation latency;
- records independent reviewer identity;
- records terminal status BLOCKED_FREEZE_FAILURE when the freeze callback fails;
- computes secret-free configuration fingerprints;
- enforces a maximum 900-second preservation latency;
- preserves evidence even when the synthetic freeze callback fails;
- marks all output synthetic and effect-free.

The controller has no provider, credential, network, payment, broker, deployment, customer, capital, venture, or worker capability.
