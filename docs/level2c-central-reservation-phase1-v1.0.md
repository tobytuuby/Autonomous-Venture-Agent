# Level 2C integrated implementation, phase 1 — central inference reservations
Version: 1.0 | Date: 2026-10-29 | Source baseline: 0235987533ea85133656bdd00116e2dbbc7404cd

This version extends the [standing usage implementation](level2c-standing-usage-evidence-v1.0.md) with centralized Agents reservations over the existing broker and polling client. It does not change venture approval, finance, launch, worker execution, model assignments, or historical phase acceptance. The [real-VM Level 2B activation record](operational-readiness/evidence/OR0.10-real-vm-mtls-activation-20261028.md) supplies prior transport context; no live service or provider was exercised in this phase.

## Contract

- Exact HTTPS route: `POST /v1/inference/reservations`. The existing TLS wrapper requires a CA-valid client certificate and SHA-256 pin membership. Only the polling identity can request reservations; capability and unknown identities are denied. All polling pins configured on one listener represent the same fixed manager actor (including overlapping rotation pins). Headers and JSON cannot choose the authenticated actor.
- The production entrypoint exposes reservations only when the operator supplies `VENTURE_BROKER_RESERVATION_ACTOR`. Without it the route returns 503. This is a separate opt-in from acknowledgement ingestion. The listener remains the existing mTLS broker; no plaintext listener, platform, service installation or activation is added.
- Agents use `RemoteStandingModel` and `PreparationPollClient.reserve_provider` on the polling client's existing verified HTTPS origin, CA, hostname and client certificate. Their config must supply `usage_policy`, an operator-owned mode-0600 copy of Control's standing policy, plus the existing polling endpoint/certificate settings. This copy supplies requested limits, never authority. The central server rereads its own authority and policy and requires an exact match. Local `StandingModel` rejects manager use; the manager entrypoint never opens or provisions a local quota authority.
- CEO inference retains the local authoritative ledger. Its first reservation establishes the central session binding over the full context and standing policy. Agents cannot create or modify that binding. Session identity, actor/role, venture/objective/rounds, epoch, endpoint/model and policy are checked before a remote reservation. This phase supports the existing preparation manager role only.
- The request contains `context, actor, role, identity, request_sha256, attempt, policy, endpoint, model`. The 64-character request digest binds the provider request, and a fresh 64-character attempt ID is durably recorded with local inference intent before HTTPS. Session/actor/logical identity determines one central call key. An exact request retry returns the same correlated receipt without another charge; changed request digest, attempt or binding is denied. Recreating a local state directory generates a new attempt and cannot reuse that paid logical call.
- Control alone writes the existing `resources.sqlite`: `exchange_sessions`, `exchange_calls`, `reservations` and the supplemental `remote_reservations` idempotency table. One IMMEDIATE/FULL-synchronous transaction commits remote session usage, daily request/token usage and the receipt binding together. The existing daily quota code is shared through `ProviderQuota`, inherited by `ServiceIdentities`; the HTTP quota interface does not read signing keys and never creates a missing authority/ledger.
- Existing maxima remain 94 daily requests, 1,540,096 reserved output tokens, at most 8 calls per session across both roles and at most 1,024 output tokens per exchange response. The standing policy can narrow these. Distinct HTTP requests use distinct SQLite connections; concurrent local and remote reservations share the same tables.
- Duplicate JSON keys, excess bodies, ambiguous framing, unknown fields, non-200 or oversized/uncorrelated responses, TLS/network/storage failures, disabled/revoked/stale authority, changed policy and quota exhaustion fail closed before inference. No redirects or local fallback. Missing response after reservation may burn capacity. The exchange conservatively holds any incomplete inference intent across restart; it does not automatically retry an ambiguous model call. A completed cached local response needs no new inference. Operator reconciliation is required for held intents; deleting/relabeling calls is not a recovery procedure.
